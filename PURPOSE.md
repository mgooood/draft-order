Fantasy Football draft position selection process


My fantasy football league does this thing where we have this huge email thread that goes between all the coaches ( N number of coaches). Where we try and figure out what the order of the draft is going to be.  It’s kind of a pain with every one emailing back and forth making selections and trying to follow who has made what choice.  So you can see that it is very difficult and this is only to select what position you will be picking or drafting in the up coming draft.  This selection process starts with the coach that was in 4th place last year, and goes down from there 5th, 6th, 7th and so on and so on then the last three to pick is the 3rd, 2nd and then 1st place winners of last year.  So if we know the coaches and last years standings then we can pretty much figure out who and in what order each coach would be selecting there drafting position.  Just for an example, say I was 6th in last years standing would mean that I am selecting my drafting position 3rd and I might choose, depending on how many coaches ( in this example we will say 12) I might chose the last position in the draft which is 12th.  This does have an advantage where I get two players at that position 12th and 13th because it’s a snake fantasy football draft.

What I would like to do if figure out how this might be done with a web site.  This will probably use AWS but that is not a requirement.  It should be dead simple (MVP).  One of the issues I see is controlling when a coach makes a selection because this is important to maintain the integrity of the order set up before the selection process starts.  The whole point here is to make a complicated process simple and it’s only used once a year so it can't be overly complicated because there would be no return on the investment of time.   However with that said its very important for the website/app to look interesting to someone that would be part of a fantasy football league, it should look as if a designer created a design for it and the CSS is created in a way that supports such a design.

Additionally I would like this to be a case study, that demonstrates how we have an initial problem or need, and we devise a plan using a technology stack to solve that problem based on a set of requirements.  The requirements might include things like solving the issue, costs, level of effort and resources.  So I would like to document the process so that it can be added to a portfolio as experience.  Meaning there will be two outcomes, a project that satisfies the original problem and case study documentation that could be used on or for a website demonstrating this experience.

General rules are as follows:

- Designs and themes are very important and should be figured out before coding, it’s very important for the site to have a consistent theme, color palette, font, use of imagery and animations.
- Follow up designs with CSS that implements these designs in a global way to each page or part of the    site maintains a consistent look and feel. We should seriously consider using some UI Kit (free of course) that will have the polish we are looking for.
- Understanding the layout of each page, this should have been done in the designs but its a step that should be done.
- Mobile first approach, site and all elements must be responsive.
- CSS variable and theming, maybe consider using Tailwind (pros and cons).
- Performance has to be considered throughout the coding process.
- Accessibility has to be part of every element or component.
- Test driven development from the start. Tests should identify broken code and where the issue is.
- MVP, always do the most simplest thing and only do more when necessary.
- Refactoring should never be done unless agreed to and asked for, the integrity of the code should be maintained.
- Discussions should always proceed making code changes, this is extremely important. 
- Javascript abstraction should always be considered in an effort to have modular reusable code that is easy to consume.



The way in which you consider these things is important that you think of this as a project that is dependent on success and being well received by the users.  Its important that when they use the website / app that its pleasing to the user, and has a look and feel that matches the purpose.  It has to be modern and can use any libraries, CSS or javascript that will make the site look the best possible.  It’s also very important that even if you are not a user of the site but you were just reviewing it that you would have a very positive impression from it. Possible tech stack could be AWS, React, typescript.  This is not a requirement but just a general idea.
